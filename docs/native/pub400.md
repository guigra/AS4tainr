# PUB400 captures for the native backend

The native backend needs PUB400 captures to settle what IBM's documentation leaves open, and to confirm the interpreter defects in `fidelity.md`. The general procedure is in `docs/golden-outputs.md`. This file is the part specific to this fork, on Linux.

## Once

1. Sign up at pub400.com. Sign on once with a 5250 client (port 23) to set the password; use letters and digits only, because PUB400 is CCSID 273.
2. The key is `~/.ssh/id_pub400`, a dedicated ed25519 key with no passphrase, so captures can run unattended. Install its public half on PUB400 from STRSQL NAMING(*SQL), replacing CHANGEME with the user profile. The statement is split with CONCAT because EDTF lines are short and `||` does not survive CCSID 273:

   ```sql
   CALL QSYS2.IFS_WRITE(
   PATH_NAME => '/home/CHANGEME/.ssh/authorized_keys',
   LINE => '<first half of ~/.ssh/id_pub400.pub>'
   CONCAT '<second half>',
   FILE_CCSID => 819, OVERWRITE => 'REPLACE',
   END_OF_LINE => 'LF')
   ```

   Then run `CHGAUT OBJ('/home/CHANGEME/.ssh') USER(*PUBLIC) DTAAUT(*EXCLUDE) OBJAUT(*NONE)`, and the same command for `authorized_keys`.
3. In `~/.ssh/config`, the `Host pub400` entry has `User CHANGEME`: put the user profile there. `ssh pub400 "system DSPLIBL"` must then answer without a password.

Never put the password in Git, a log or a chat.

## Capturing

```sh
GOLDEN_LIB=<a library of the account> GOLDEN_HOME=/home/<user> \
  tools/golden/golden.sh -l tools/golden/native1.txt -f tools/golden/native1
```

`tools/golden/golden.sh` is the Linux counterpart of `golden.ps1`. It takes the same lists, plus `@LIB@` and `@HOME@`, which it replaces from `GOLDEN_LIB` and `GOLDEN_HOME`; `-n` shows the remote script without sending it. Results go to `target/ibmi/golden/<name>.txt` and are never committed. A test that uses one cites it as `// Source: golden capture tools/golden/native1.txt n1_mon (PUB400, IBM i 7.5, YYYY-MM-DD)`.

`tools/golden/native1.txt` covers:

| Capture | Question |
| --- | --- |
| `n1_mon` | Nested MONITOR: does the outer ON-ERROR take an error the inner group does not? (interpreter defect 1) |
| `n1_crt_cst` | An assignment to a CONST parameter: the compiler's message (defect 2) |
| `n1_ovl` | `OVERLAY(field:*NEXT)`: the subfields' positions and the data structure's size (defect 3) |
| `n1_crt_fwd` | A CONST parameter passed on as a writable one: the compiler's message |
| `n1_alias` | Two reference parameters that are one variable |
| `n1_div`, `n1_ovf` | The escape message IDs of status 00102 and 00103, unmonitored |

The programs write their results to `gn1.out` with `QSYS2.IFS_WRITE_UTF8`, because a DSPLY under `system` goes to QSYSOPR, a queue PUB400 users share.
